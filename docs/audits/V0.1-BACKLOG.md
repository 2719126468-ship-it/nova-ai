# NOVA V0.1 开发任务清单

本清单按依赖和验收顺序排列。V0.1 是唯一当前主线；Documents、Research 搜索、多模态和商业化暂不抢占核心 Chat 资源。

## Sprint 0 — 规格与数据基础

### NOVA-001：冻结 V0.1 API 与消息状态合同
- 优先级：P0
- 工作：定义会话、消息、模型状态、SSE 事件、错误码、取消语义和重试规则；建立 /api/v1 规范，规划旧 /api 兼容期。
- 验收：API 文档/示例与实现一致；每种消息状态有明确转换规则；错误码覆盖配置缺失、上游超时、限流、额度耗尽和 Provider 错误。

### NOVA-002：加入数据库 migrations
- 优先级：P0
- 工作：以 schema version 或迁移表管理 DDL；把新表与字段变更迁移化。
- 验收：新 SQLite 文件初始化成功；现有 0.1 数据库可升级；重复启动不会重复应用迁移；CI 覆盖升级路径。

## Sprint 1 — Model Gateway

### NOVA-003：Provider 接口与注册表
- 优先级：P0
- 工作：统一非流式、流式、模型目录、能力、超时、取消和错误格式；密钥仍由服务端环境/密钥存储提供。
- 验收：Chat 不直接依赖具体供应商；至少一个 OpenAI-compatible Provider 通过 mock 测试；Provider 错误不会泄露密钥。

### NOVA-004：服务端模型目录与状态语义
- 优先级：P0
- 工作：模型 ID、展示名、Provider、enabled、capabilities、contextLimit、default/status；区分 configured、enabled、healthy、degraded、unavailable、unknown。
- 验收：/api/v1/models 由服务端配置产生；未实际健康检查的模型不显示“可用/已连接”；前端可选择 enabled 模型。

### NOVA-005：低成本资源治理
- 优先级：P0
- 工作：每用户+IP 限流、AI 并发上限、单请求长度限制、上下文预算和请求超时；默认不自动切换模型。
- 验收：超额请求返回清晰 429/503；并发恢复；失败不会反复重试；用量只记录供应商实际返回的 usage，未知时为空。

## Sprint 2 — Chat 主流程

### NOVA-006：SSE 流式输出
- 优先级：P0
- 工作：建立流式对话端点；发送 message_start、message_delta、message_complete、error 等事件；处理代理缓冲和连接中断。
- 验收：浏览器收到增量 token；首个增量不需等待完整回答；消息完成后保存最终内容；错误状态可恢复。

### NOVA-007：停止生成与取消传播
- 优先级：P0
- 工作：客户端取消、请求断连处理、服务端 AbortController 与 Provider signal 传递；限制活跃任务数。
- 验收：停止按钮可用；上游 fetch 被 abort；断连不会继续消耗请求；消息不会永久处于 streaming 状态。

### NOVA-008：会话整理
- 优先级：P0
- 工作：重命名、删除确认、最近会话排序；视范围增加标题搜索与归档。
- 验收：修改后刷新仍保留；跨用户操作返回 404/403；删除规则明确。

### NOVA-009：消息操作与版本规则
- 优先级：P0
- 工作：复制、编辑用户消息并重新生成后续回答、重新生成 assistant 回复、失败重试；定义消息覆盖/版本策略防止重复和错位。
- 验收：消息顺序、上下文和历史不重复；用户可明确知道哪条回答被替换/保留；编辑后的上下文按预期重算。

### NOVA-010：Chat UI 模型切换与代码体验
- 优先级：P0
- 工作：顶部模型选择器、状态标记、Markdown/GFM、代码语法高亮、复制代码/回复；Enter 发送、Shift+Enter 换行、失败保留草稿。
- 验收：只显示可选择模型；代码块高亮和复制准确；窄屏可操作；生成和失败状态明确。

### NOVA-011：上下文管理
- 优先级：P0
- 工作：按模型 contextLimit 管理历史；预留 system/developer prompt；预算超限时裁剪/摘要并告知；保护当前输入不被截断。
- 验收：多轮对话超限测试通过；不得将字符估算当作精确 Token 计量。

## Sprint 3 — 权限、测试与上线准备

### NOVA-012：跨用户数据隔离测试
- 优先级：P0
- 工作：两个用户分别创建项目/会话；测试读取、更新、删除、消息写入、项目关联的越权场景。
- 验收：A 无法探测或操作 B 资源；未授权时统一返回 404 或按合同返回 403。

### NOVA-013：Provider 与流式故障测试
- 优先级：P0
- 工作：覆盖 Provider success、401/403、429、5xx、超时、空响应、畸形流、客户端取消。
- 验收：错误分类正确；无伪造消息；不会遗留生成锁；API Key 不进入日志/错误返回。

### NOVA-014：Usage 与管理员可观测性
- 优先级：P0
- 工作：调用次数、Provider/model、状态、时长、供应商 usage、错误类别；管理员健康和错误概览。
- 验收：可聚合按天/用户/模型的请求数；明文提示词默认不落日志；数据不准时明确标记未知。

### NOVA-015：移动端与端到端回归
- 优先级：P0
- 工作：Playwright 登录、聊天、历史、停止、错误恢复、项目；覆盖 360/390/768/1280 px。
- 验收：核心任务无需桌面设备；无横向溢出；按钮可触达；键盘与输入行为符合移动端习惯。

### NOVA-016：账户数据生命周期
- 优先级：P0（公开注册前）
- 工作：账号数据导出、删除确认、会话撤销、删除保留策略和隐私文案。
- 验收：用户可导出自己的记录并删除账户；级联删除和备份保留规则明确。

## P1 / 暂缓

- NOVA-102 Research 搜索 Provider、来源管理和研究报告。
- NOVA-103 文件上传/解析（先完成 SEC- 上传威胁控制）。
- NOVA-104 更多 Provider 与模型能力。
- NOVA-105 PostgreSQL/共享限流 Store（有多实例或并发需求时再做）。

## Definition of Done

每项任务合并前必须满足：
1. 通过 API/组件测试；涉及用户权限的必须有跨用户负向测试。
2. 错误、加载、空数据和取消状态均有 UI。
3. 不把模拟内容标记成真实服务结果。
4. 不引入真实 API Key、用户私密内容或数据库文件到 Git。
5. CI 的依赖安装、API 测试和生产构建全部通过。
6. 文档与实际行为同步更新。
