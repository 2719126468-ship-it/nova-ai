# NOVA 技术债清单

审计基线：2026-11-06 / main @ `69bec32e1fbb8bfc2a6bf233737e2db414332634`

## P0 — V0.1 完成前必须处理

| ID | 技术债 | 影响 | 建议处理方式 | 验收标准 |
|---|---|---|---|---|
| TD-01 | Provider 只有非流式 JSON 调用 | 长回复等待时间长；无法停止；断连不能取消上游 | 实现 SSE adapter，支持 AbortSignal、超时、断连清理和事件状态 | token delta 连续输出；停止和断连会取消上游；消息不会卡在生成中 |
| TD-02 | 没有真正的 Model/Provider Registry | 只能配置单模型；UI 无选项；配置状态被当作可用状态 | 建立统一 Provider 接口、服务端模型目录和模型能力元数据；密钥保留在 env/secret store | /models 返回明确配置、enabled、capabilities 和 status；状态不凭 env 存在就称健康 |
| TD-03 | 会话操作缺失 | 用户无法整理长期聊天 | 增加重命名、搜索/归档（按范围决定）、消息编辑、重试/重新生成接口 | 对话元数据可持久化；编辑后后续消息顺序与上下文一致 |
| TD-04 | 消息操作尚不完整 | 常用 AI 工作流仍缺回答版本历史与撤销 | 已增加复制、用户消息编辑、末轮 assistant 重新生成和最新失败/取消回答重试；替换只在成功时提交，失败/取消保留旧分支 | 编辑/重试成功和失败测试通过；旧分支不会因 Provider 失败或停止而丢失；剩余补回答版本/撤销 |
| TD-05 | 尚无 Provider Token 级上下文预算 | 模型窗口和实际 Token 数未知，固定消息条数不等于上下文预算 | 已增加 AI_MAX_CONTEXT_CHARS 字符预算，优先保留最近完整轮次；下一步按 Provider 元数据增加 Token 预算/摘要 | 当前字符预算超限时保留用户输入或明确拒绝；不把字符估算冒充精确 Token；后续增加各模型 contextLimit 校验 |
| TD-06 | 缺少用户维度配额与并发控制 | 少数用户可耗尽共享免费额度 | per-user + IP 限流、单用户并发上限、请求长度和超时配置；单实例先用内存/SQLite 方案 | 并发和配额超限返回结构化 429/503；有自动化测试 |
| TD-07 | Projects 无 Conversation 关联 | 项目不具备 PRD 要求的“项目内对话” | 已加入 project_conversations 迁移、归属校验 API，以及 Studio 关联/移除入口 | 双账号无法跨账号关联；移除链接不删除会话；项目/会话删除通过外键级联清理关联行 |
| TD-08 | 没有 schema migrations | 后续加表/改字段容易导致升级丢数据 | 引入 migration 目录和 schema version；启动仅执行待执行迁移 | 新库与旧库均可升级；迁移重复执行安全；CI 测试旧版升级 |
| TD-09 | 测试覆盖过薄 | 当前绿色 CI 无法证明关键安全/聊天路径 | 增加双用户隔离、会话过期、管理员、Provider success/error/timeout、SSE 取消与限流测试 | 核心路径与权限边界具备自动化回归 |
| TD-10 | API 尚未版本化 | 以后重构客户端/接口缺少兼容空间 | 新增 /api/v1；旧 /api 设兼容期/重定向策略（非 GET 请求不要盲目重定向） | OpenAPI/接口文档与实现一致；客户端切换完成 |
| TD-11 | 用户数据控制能力不足 | 公开使用前缺乏完整隐私生命周期 | 加入账户删除、数据导出与数据保留说明；操作前二次确认 | 用户可导出并删除自己的账户与内容，测试验证级联规则 |
| TD-12 | 模型与用量运营不可观测 | 无法判断哪个 Provider 失败/资源消耗多少 | usage_logs 记录 requestId、userId、provider/model、耗时、状态、供应商返回 usage（如有） | 管理后台可查看聚合用量；日志不含明文密钥/不必要提示词 |

## P2 — 后续能力

- 多模态文件/图片/语音能力；按合法可用 Provider 能力逐项添加。
- 多人协作、团队权限和项目共享。
- 复杂研究代理和异步任务编排。
- 收费、订阅、账单等商业化能力（当前 PRD 明确不做）。

## 实施原则

- 先解决 TD-01 至 TD-12 中影响 V0.1 真实对话、安全和维护的项目。
- 不为“技术先进”而提前引入微服务、Redis、队列或 Kubernetes。
- 每项技术债都应带验收标准和自动化测试；CI 变绿只是必要条件，不是产品完整性的充分条件。
