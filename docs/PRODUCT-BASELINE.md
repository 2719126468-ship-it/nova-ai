# NOVA AI 正式产品基线

- 文档版本：NOVA-PRD-1.0
- 产品阶段：MVP / V0.1 规划
- 产品负责人：个人开发者
- 当前商业模式：Free-first（当前免费，不承诺无限量）
- 当前代码基线：`main` 分支；2026-11-06

## 1. 产品定位

**NOVA AI — AI Conversation & Work Platform**

NOVA 是面向广泛用户的免费优先 AI 对话与工作空间，帮助用户进行思考、学习、研究、创作和日常工作。产品借鉴 OpenAI 产品体验中的清晰信息层级、连续对话和工作区组织方式，但保留独立的 NOVA 品牌，不复制第三方商标或专有素材。

## 2. 资源与商业边界

NOVA 由个人开发者主导，早期资源受限。架构必须可替换、可降级、可维护：

- 不绑定单一模型供应商；Provider 由服务端适配。
- 只使用获准用于该场景的模型服务和免费额度，不通过共享泄露密钥、批量账号或规避供应商限制维持服务。
- 清楚说明当前可用模型、资源限制和失败原因。
- 不承诺永久免费、无限请求或所有模型永久可用。
- 上游额度不足、超时或不可用时，明确返回可理解的错误；未经用户或产品策略允许，不自动切换模型。
- 不将“已配置”表述为“已健康可用”；模型健康状态必须来自真实检查或近期请求结果。

## 3. 目标用户与优先场景

目标用户：所有人。开发顺序先覆盖最常见任务：

| 人群 | 常见需求 | 首批能力 |
|---|---|---|
| 普通用户 | 问答、日常助手 | AI Chat |
| 学生 | 解释、学习、总结 | 多轮对话、后续文件分析 |
| 开发者 | 编程、调试、代码解释 | 代码块、模型选择、长上下文治理 |
| 创作者 | 构思、写作、改写 | 对话保存、Projects、Documents |
| 研究人员 | 资料整理、分析 | Research（后续版本） |
| 专业用户 | 复杂任务 | 多模型与项目工作区（逐步扩展） |

## 4. 产品体验原则

- 默认浅色主题，支持深色主题。
- 桌面端采用清晰的工作区导航；移动端采用可收起/抽屉式导航。
- 对话内容优先，输入框明显、支持多行编辑。
- 留白、细边框、适度圆角和克制阴影；保持 NOVA 独立品牌识别。
- 重要状态必须可见：生成中、完成、失败、取消、模型未配置、额度受限。
- 用户输入失败时保留草稿；失败消息不得伪装为成功答案。

## 5. 版本目标

### V0.1 — 核心对话系统（当前唯一主线，P0）

验收主路径：

用户打开 NOVA → 登录 → 选择服务端实际可用的模型 → 开始多轮对话 → 逐字/分块收到回复 → 可停止生成 → 会话与消息持久化 → 刷新后继续对话。

必须具备：

- 注册、登录、退出、账户资料和密码管理。
- 服务端会话认证与跨用户数据隔离。
- 新建、列出、打开、重命名和删除会话。
- 多轮上下文、流式输出、取消生成和失败恢复。
- Markdown、GFM、代码高亮和复制。
- 复制回复、重试/重新生成、编辑用户消息。
- 模型目录来自服务端配置；显示供应商、能力、状态和默认模型。
- 请求长度、上下文预算、并发和频率限制。
- Provider 超时、取消、结构化错误和用量记录（上游未提供精确 Token 时不得编造）。
- 移动端可完成登录、聊天、历史查看和生成控制。

Projects 的 P0 基础能力：创建、编辑、删除项目；将对话关联至项目并查看项目内会话。

### V0.2 — AI 工作空间（P1）

- Markdown Documents：创建、编辑、重命名、删除、自动保存。
- 文档归入项目；从 AI 对话生成文档。
- 文件上传与解析先设置严格类型、大小和数量限制。
- 不在此阶段建设实时多人协同编辑。

### V0.3 — Research 与模型扩展（P1）

- 真实搜索 Provider（只有接入并获得结果时才显示“已搜索”）。
- 研究计划、来源链接、结构化报告、保存和 Markdown 导出。
- 更多合法 Provider 与模型能力声明。
- 来源、事实和模型推测需要明确区分。

### V1.0 — 稳定公开版本

- 部署、备份恢复演练、监控告警、隐私说明和安全审计。
- 多实例前评估 PostgreSQL 与共享限流存储。
- 账号删除/数据导出、滥用管理和完整运营流程。
- 公开发布前完成端到端、压力和跨用户隔离测试。

## 6. MVP 成功标准

| 维度 | 验收目标 |
|---|---|
| 对话 | 连续多轮对话正确关联上下文 |
| 流式 | 回复逐步显示；断连或停止不会留下永久“生成中”状态 |
| 历史 | 刷新后会话和消息仍可恢复 |
| 模型 | 只展示服务端配置且真实可用/状态明确的模型 |
| 操作 | 重命名、删除、复制、编辑和重试行为正确 |
| 权限 | 用户 A 无法读取、修改或删除用户 B 的资源 |
| 异常 | 未配置、超时、限流、额度耗尽和上游错误均清晰反馈 |
| 移动端 | 手机端完整完成登录、聊天、历史和停止生成 |
| 成本 | 具备每用户/来源限流、并发控制和用量统计 |
| 安全 | 前端不含模型密钥；会话与管理员权限由服务端校验 |

## 7. 长期产品规则

1. 先做完整，再做庞大。
2. 先保证可替换，再增加模型。
3. 先保证安全与用户数据隔离，再公开服务。
4. 先保证稳定，再追求流量。
5. 学习优秀产品的交互原则，不照搬其基础设施规模。
6. 没有真实搜索、模型调用或文件处理结果时，不声称已完成。
7. 所有 API Key 只存在于服务器环境或受控密钥管理中，不进入浏览器构建产物和 Git。
